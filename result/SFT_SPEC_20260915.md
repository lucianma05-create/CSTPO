# SFT 数据构建规格（2026-09-15 冻结版）

> 本文件是 SFT 数据构建的唯一权威规格。SFT / RL / 推理三处代码必须与本文件一致；
> 任何改动先改本文件，再同步三处。关联文档：03§4（SFT 与采样概率）、02（数据规范）。

## 1. 基座与规模

- 基座模型：**Qwen3-8B**（Qwen3 无 7B；单卡 A100-80G 可训练）
- 三任务各自独立 SFT + RL：P4G / CraigslistBargain / ESConv 各一个最终策略网络

## 2. 输出结构与标签

### 2.1 每轮输出 = 标签前缀 + 话语（同一自回归网络）

```
<策略标签>\n<话语>
```

- 标签为**纯文本**、单独一行、后跟换行再说话语；**不加特殊 token**（不扩词表）
- 标签串模板与分隔符为全局常量，SFT 渲染、RL 采样、推理展示三处逐字节一致
- 标签空间（收敛后）：
  - ESConv：官方 8 类（Question / Restatement or Paraphrasing / Reflection of
    feelings / Self-disclosure / Affirmation and Reassurance / Providing
    Suggestions / Information / Others）；数据变体归一化：Questions→Question、
    Other→Others
  - P4G：27 类收敛为 **13 类**（合并方案用户认可，实测 13 类全部出现）：
    捐赠请求 5 合一（donate_request）、inquiry 3 合一、inquiry 反应 3 合一
    （inquiry_response）、会话功能 6 合一（social）、说服手段 8 保留、
    off-task/other→other
  - CB：草案 v2 的 5+1 类（propose_price / inquire / inform / stance / social /
    other 占位）；offer/accept/quit 为任务事件不作策略标签；unknown/None 排除
- 标签合法性由 **trie 约束采样**保证（Qwen3 真实 tokenizer 适配 + 手算例验证；
  P0 的 CharTokenizer 仅参考实现）

### 2.2 标签训练口径

- SFT：assistant 回合带标签前缀，**标签位置 loss mask**（话语 SFT 口径）——
  SFT 只学 P(utterance|history, label)，标签分布留给 RL 学
- RL：标签位置按 trie 合法支持求 KL/概率；话语位置按词表支持（03§3）
- 多标签政策：数据摸底三任务均实质单标签（ESConv 0 多标签、P4G label_2 非空
  0.3%、CB 0 多标签）——"主导交互意图"单标签政策成立（03§4）

## 3. 数据来源与分组

- 主体（80%）：真人语料（P4G / CB / ESConv 官方 train；标签覆盖率实测：
  **ESConv 100%**（16682 回合）、**CB 56%**（24175 回合中有效标签 13594，
  任务事件 3791 排除、unknown/None 6790 排除）、**P4G 12%**（8484 回合中
  带 persuader 标签 1050；另 1329 条标注属 persuadee 侧，不在 Actor 分类））
- 香草子集（20%）：vanilla 画像 + Cog-Sim 生成——用 v4.2 管线**新提取种子**
  （避开校准占用与 val/test 分组；esconv 现有 40 种子已全被校准占用），
  vanilla 画像自由结束跑对话
- 无标签回合统一用**占位标签**（`<unlabeled>`，不在 trie 合法集内）+ loss mask
  进入话语 SFT——模型学 P(utterance|history, label 占位)，占位路径 RL 时不可达；
  P4G 因此无需大规模补标（1050 条真标签足够学标签分布，RL 阶段再扩展）。
  补标降级为可选增强：如需补标，flash + 人工抽查 30 条，报告后使用
- 分组防泄漏：SFT 只用 train；评估用 val/test + 校准留出 30 条；种子与对话
  不得跨集

## 4. 格式与序列约定

- messages 格式（HF chat 通用）：`{"messages": [{"role": ..., "content": ...}]}`
- **样本以 user 消息开头**（防顺序漂移）：原始对话开头的 assistant 消息丢弃
- 角色映射（写死 + 构建时断言）：
  - ESConv：seeker→user、supporter→assistant
  - P4G：persuadee→user、persuader→assistant
  - CB：seller→user、buyer→assistant
- **同角色连续消息合并为一条**（换行拼接），保证严格交替
- 前缀口径：种子构建的样本历史 = `prefix_turns(seed)`（2 用户回合、以用户消息
  结尾）+ 全量续写；真人全段语料不做截断（其开头即真实开头，同样保证 user 开头）
- 每条 assistant 回合切一条样本（历史 = 该点之前全部；loss 只算目标回合的
  话语 tokens，标签 tokens 按 2.2 mask）
- 系统提示 = 论文香草提示（与 agent.py 推理接口一致，逐任务固定）

## 5. 长度与窗口

- 上下文窗口：**4096 tokens**（实测 Qwen3-8B tokenizer：esconv P99=1162/max=2333、
  p4g P99=847/max=1464、cb P99=487/max=712——P99×1.5 均低于 4096 下限，
  4096 覆盖全部样本且留 ≥1.8× 余量）
- **推理生成配置（三处一致，2026-09-16 冻结）**：贪心 + suppress 特殊 token
  （<|url|> 等 5 类）+ repetition_penalty=1.15——见 TRAIN_CONFIG 生成配置三件套；
  verl 接入时必须沿用同一配置，不得另行调参
- 已构建规模（data/sft/<task>/）：esconv 14114（真人 13267 + 香草 847）、
  p4g 8572（7671 + 901）、cb 17039（16464 + 575）；香草占比 3-11%，
  最终 8:2 混合在训练装配阶段通过真人下采样达成（可选）
- 话语目标长度对齐推理设置（agent 推理 max_tok=150）；超长目标话语截断于
  窗口内，构建时统计截断率

## 6. 验证闭环

- SFT 后：judge 手段（锚定提示 + 3 次聚合，`judge_with_aggregation`）在
  校准留出 30 条上 A/B 对比香草提示，同预算；未超过香草提示 → 回炉数据/提示
- 覆盖率与质量报告：标签覆盖率、补标一致性（人工抽查）、截断率、长度分布
