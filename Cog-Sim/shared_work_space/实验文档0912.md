## 1. 状态与符号（继承 0911 §1、§3、§5）

$$z_t=(C_t,E_t),\qquad C_t=(B_t,D_t,I_t),\qquad E_t=(v_t,r_t,c_t)$$

- 节点结构：`{id, type, content, strength}`，$strength\in[0,4]$；数量限制 $|B|\le4,\ |D|\le3,\ |I|\le3$。
- 节点扩展字段（0911 未定义，实现补充）：
  - `polarity ∈ {approach, avoid}`：Desire/Intention 的方向（Belief 无极性）；
  - `core ∈ {true, false}`：核心/外围节点，非核心节点优先淘汰；
  - `active ∈ {true, false}`：非核心节点强度 $<0.5$ 自动退役（inactive），强度回升至 $\ge0.7$ 重新激活；
  - 新增 Belief 可标 `conflicts_with`：声明与已有 Belief 的矛盾关系。
- 情绪：$v_t\in[-1,1]$（效价），$r_t\in[0,1]$（唤醒），$c_t$ 为展示类别（集合见 0911 §5，不参与动力学）。
- 认知习惯参数（程序侧保存，不直接输入 LLM）：

$$\Theta_u=(\eta_R,\tau_A,\tau_R),\qquad 0\le\tau_A<\tau_R\le1$$

- Appraisal 为当轮中间变量，不入长期状态：

$$A_t=(GC_t,CP_t,FE_t)\in[-1,1]^3$$

理论根基总览：$C_t$ 为 BDI 状态（§6），$E_t$ 为维度情绪状态（§7），$A_t$ 为 Appraisal Theory 的当轮中间变量（§7）。

## 2. 模块总览与执行路径

| 模块 | 职责 | 理论根基 | 对应代码 |
|---|---|---|---|
| **Action Type Classifier**（ATC） | 判断 $q_t$ | —（任务中立的对话动作分类） | `routing/mode_classifier.py` |
| **Target & Route Inference Engine**（TRIE） | 提取 $p_t$ 与四个等级特征，推断 $R_t$ | **ELM**（精细加工可能性模型） | `routing/route_features.py`、`route_controller.py` |
| **Judgment Estimation Engine**（JEE） | 估计 $d_t$ 与相关节点，阈值映射 $J_t$ | **SJT**（社会判断理论） | `routing/discrepancy.py`、`judgment_controller.py` |
| **RJ-Constrained Cognitive Transition Engine**（RJ-CTC） | Contract 构造、Engine 提案、确定性约束应用得 $C_{t+1}$ | **BDI**（信念-愿望-意图模型） | `cognitive/rj_contract.py`、`cognitive_engine.py`、`state/updater.py` |
| **Emotion Update Engine**（EUE） | 计算 $A_t$（当轮中间变量）与 $E_{t+1}$ | **Appraisal Theory**（认知评价理论）+ **Dimensional Emotion Theory**（维度情绪理论） | `affect/emotion_engine.py` |
| **Cognitive-Grounded Response**（CGR） | Influence：Engine 出认知提案与 $plan_t$，由统一 NLG 生成 $u_{t+1}$（两步） | —（BDI-E 状态的部分揭示表达） | `generation/user_response.py` |
| **State-Revealing Response**（SRR） | Elicit：合并调用出 A 提案与 $plan_t$、记录 revealed_items | —（BDI-E 状态的部分揭示表达） | `generation/user_response.py` |
| **Emotion-Regulating Response**（ERR） | Social：合并调用出 A 提案与 $plan_t$（仅低幅度情绪调节） | —（BDI-E 状态的部分揭示表达） | `generation/user_response.py` |
| **Conversation End Detector**（CED，辅助） | 任务中立的 user_done 分类 | —（任务中立启发式） | `generation/conversation_end.py` |

三种模式的执行路径：

$$\begin{cases} q_t=\text{Influence}: & \text{ATC}\rightarrow\text{TRIE}\rightarrow\text{JEE}\rightarrow\text{RJ-CTC}\rightarrow\text{EUE}\rightarrow\text{NLG}\\[2pt] q_t=\text{Elicit}: & \text{ATC}\rightarrow\text{SRR}\rightarrow\text{EUE}\rightarrow\text{NLG}\\[2pt] q_t=\text{Social}: & \text{ATC}\rightarrow\text{ERR}\rightarrow\text{EUE}\rightarrow\text{NLG} \end{cases}$$

每轮最后统一执行 CED。Elicit / Social 下 $C_{t+1}=C_t$（0911 §35、§36），但 $E_{t+1}$ 允许变化；SRR/ERR 的合并调用**必须**以 agent 本轮回复 $a_t$ 为输入（否则答非所问）。三模式的话语 $u_{t+1}$ 均由**统一 NLG 步骤**生成：在 EUE 算完 $A_t,E_{t+1}$ 之后，基于 $(C_{t+1},E_{t+1},a_t,plan_t,q_t)$（Elicit 另加 $\mathcal R_t$）单独调用生成（0912 收敛，见 §8）。

### 2.1 Robustness 与 debug 开关（Validation 1.1 收敛）

**结构化输出全链路兜底**：任何 LLM 格式异常不得击穿 `simulate_turn`。流程：parse 失败 → 本地修复 → 1 次 LLM 修复重试 → 组件 safe fallback（全部触发记 `[robustness]` 审计 note，目标 `TurnCrashRate=0`，fault injection 12 例已验证）：

| 组件 | safe fallback |
|---|---|
| ATC | 规则兜底（问号→Elicit，否则 Influence） |
| TRIE | Rel=Arg=0.5, Cue=0.2, Press=0.5, p_t=∅ |
| JEE | d_t=0.5, I_t=∅（正常走阈值映射） |
| Engine | ΔC=0 + 最小 plan（不猜任何新认知变化） |
| EUE | GC=CP=FE=0、无逐 Desire 标注、neutral 提案 |
| SRR/ERR | C 冻结、无揭示、中性 appraisal、mode 相符最小 plan（Social 禁承诺） |
| NLG | 1 次重试 → mode 安全话语（不含新承诺） |
| CED | 关键词规则 |

**debug 开关**：纯审计字段（ATC/CED 的 `reason`、TRIE 的 `dominant_cues`）仅 debug 模式请求（`UserSimulator(debug=...)` / `run_sim --no-debug`）；debug 模式另输出单轮 `chain_trace`（q→p→R/d→J→ΔC→A→E→plan→u 链路追踪）。

## 3. Action Type Classifier（0911 §8、§9）

$$q_t=\text{ATC}\bigl(H_t,\ a_t\bigr)\in\{\text{Influence},\text{Elicit},\text{Social}\}$$

内部步骤：

1. LLM 按 0911 §9 的 prompt 分类（输入仅最近 6 条历史与 $a_t$，不传 $P/C_t/E_t$）；

## 4. Target & Route Inference Engine（收敛自 0911 §13–§17、§34）

> **理论根基：ELM**（Elaboration Likelihood Model，精细加工可能性模型，Petty & Cacioppo）。Central route 对应高精细加工（系统性评估论据质量：Rel、Arg），Peripheral route 对应低精细加工（依赖外围线索：Cue）；$\eta_R$ 为用户精细加工倾向参数，§4.2 的 CentralScore / PeripheralScore / $p_C$ 为 ELM 双路线的程序化表达。

$$(p_t,\ R_t)=\text{TRIE}\bigl(C_t,\ a_t;\ \eta_R\bigr)$$

（内部中间变量 $Rel_t,Arg_t,Cue_t,Press_t,p_C$ 不列于模块级签名；按以下两步展开。）

内部步骤：§4.1 特征与目标提取（一次 LLM 调用）→ §4.2 Route 决策（程序公式）。

### 4.1 特征与目标提取（一次 LLM 调用）

$$\bigl(Rel_t,\ Arg_t,\ Cue_t,\ Press_t,\ p_t\bigr)=\text{TRIE}_{feat}\bigl(C_t,\ a_t\bigr)$$

内部步骤：

1. LLM 一次调用输出五个等级字段（`dominant_cues` 为纯审计字段，仅 debug 模式请求，§2.1）；
2. 等级映射统一：

$$\text{low}=0.2,\qquad\text{medium}=0.5,\qquad\text{high}=0.8$$

得到 $Rel_t,Arg_t,Cue_t,Press_t\in\{0.2,0.5,0.8\}$，$p_t=TargetProposition(a_t)$；
3. LLM 失败时兜底：$Rel=Arg=0.5,\ Cue=0.2,\ Press=0.5,\ p_t=\varnothing$。

- **InteractionPressure（交互压力）** 为 0911 §34 公式新增的语义分量，定义严格任务中立：*只衡量该回复对用户即时回应的需求强度*（high=deadline/最后通牒/逼问；medium=普通提问或温和建议；low=闲聊/纯信息，不回应无后果），与说服力、话题重要性、用户情绪反应解耦。Influence 由 TRIE 输出，Elicit/Social 由合并生成调用输出。

### 4.2 Route 决策（程序公式）

$$R_t=\text{TRIE}_{route}\bigl(\eta_R,\ Rel_t,\ Arg_t,\ Cue_t\bigr)$$

$$\boxed{CentralScore_t=\eta_R\cdot Rel_t\cdot Arg_t},\qquad \boxed{PeripheralScore_t=(1-\eta_R)\cdot Cue_t}$$

$$p_C=\begin{cases} \eta_R, & CentralScore_t+PeripheralScore_t<\delta=0.05\\[2pt] \dfrac{CentralScore_t}{CentralScore_t+PeripheralScore_t+\epsilon}, & \text{otherwise} \end{cases}\qquad(\epsilon=10^{-8})$$

$$R_t=\begin{cases} \text{Central}, & p_C\ge0.5\\ \text{Peripheral}, & p_C<0.5 \end{cases}\quad(\text{deterministic，benchmark 默认})$$

训练 rollout 可选 $R_t\sim Bernoulli(p_C)$（`--route-mode bernoulli`）。

## 5. Judgment Estimation Engine（0911 §18–§20）

> **理论根基：SJT**（Social Judgment Theory，社会判断理论，Sherif）。用户以既有立场为锚，按新命题与锚的立场距离 $d_t$ 落入接受域 / 非承诺域 / 拒绝域——对应 SJT 的 assimilation / noncommitment / contrast 判断；域边界由 $\tau_A,\tau_R$ 刻画（§5.2）。

$$(J_t,\ \mathcal I_t)=\text{JEE}\bigl(p_t,\ C_t;\ \tau_A,\ \tau_R\bigr)$$

（内部中间变量 $d_t$ 不列于模块级签名；按以下两步展开。）

内部步骤：§5.1 距离估计（LLM）→ §5.2 Judgment 阈值映射（程序）。

### 5.1 距离估计（LLM，输入 $p_t$ 与当前状态）

$$\bigl(d_t,\ \mathcal{I}_t\bigr)=\text{JEE}_{est}\bigl(p_t,\ C_t\bigr),\qquad d_t\in\{0.2,0.5,0.8\}$$

内部步骤：

1. LLM 输出 stance 等级（low/medium/high）与相关节点 id 列表——不输出 Judgment、不输出任何解释字段；
2. 等级映射为 $d_t$（§4.1 的映射表）；$\mathcal{I}_t$ 仅保留存在于 $C_t$ 的 id（程序过滤幻觉 id）。

$\mathcal{I}_t$ 为 `relevant_current_state`：与 $p_t$ 最相关的 B/D/I 节点 id 列表，供 Updater 的 Reject 方向检查定位 Belief（§6.3 规则 3）。

### 5.2 Judgment 阈值映射（程序）

$$J_t=\text{JEE}_{thr}\bigl(d_t,\ \tau_A,\ \tau_R\bigr)=\begin{cases} \text{Accept}, & d_t\le\tau_A\\ \text{Noncommit}, & \tau_A<d_t<\tau_R\\ \text{Reject}, & d_t\ge\tau_R \end{cases}$$

$R_t$ 与 $J_t$ 独立（0911 §20），构成六种组合。

## 6. RJ-Constrained Cognitive Transition Engine（收敛自 0911 §21–§31）

> **理论根基：BDI**（Belief-Desire-Intention，信念-愿望-意图模型，Bratman / Rao & Georgeff）。$C_t=(B,D,I)$ 为实用推理（practical reasoning）的三元组：信念为世界模型、愿望为目标、意图为行为承诺；§6.2–§6.3 的更新约束（Intention 需要 B/D 支撑、冲突信念衰减、核心节点保护）是 BDI 理性承诺动态的程序化表达，RJ 合约则给出该动态的社会认知边界（§6.1）。

$$C_{t+1}=\text{RJ-CTC}\bigl(P,\ C_t,\ E_t,\ H_t,\ a_t,\ p_t,\ R_t,\ J_t\bigr)$$

（$\Theta_u=(\eta_R,\tau_A,\tau_R)$ 为固定参数；$Card$ 由 $\Theta_u$ 编译，$\mathcal I_t$ 由 JEE 提供——均为内部步骤的输入，不列于模块级签名。）

内部步骤：

1. **Contract 构造**（§6.1）：$(R_t,J_t)\to Contract$，数值限幅 $Limit(R,J,type)$ 程序侧保存；
2. **Engine 提案**（§6.2）：$(\widehat{\Delta C}_{t+1},\ plan_t)=Engine(P,Card,C_t,E_t,H_t,a_t,p_t,R_t,J_t,Contract)$；
3. **Deterministic Updater**（§6.3）：$C_{t+1}=Apply(C_t,\widehat{\Delta C}_{t+1},R_t,J_t,\mathcal I_t)$；
4. **Robustness**（Validation 1.1）：Engine 结构化输出解析失败 → $\Delta C=0$（不更新任何 B/D/I，§2.1）。

### 6.1 Contract 构造与限幅表

六种 $(R_t,J_t)$ 组合的自然语言合约沿用 0911 §22–§27 原文。程序侧限幅（`rj_contract.py`，每类节点允许的最大 $|\Delta strength|$）：

| (Route, Judgment) | belief | desire | intention |
|---|---|---|---|
| Central + Accept | 1.0 | 0.5 | 0.8 |
| Central + Noncommit | 0.4 | 0.2 | 0.3 |
| Central + Reject | 0.4 | 0.2 | 0.5 |
| Peripheral + Accept | 0.3 | 0.1 | 0.6 |
| Peripheral + Noncommit | 0.2 | 0.0 | 0.2 |
| Peripheral + Reject | 0.2 | 0.0 | 0.5 |

### 6.2 Engine 提案（一次 LLM 调用，仅认知 + 反应计划）

$$\bigl(\widehat{\Delta C}_{t+1},\ plan_t\bigr)\leftarrow Engine\bigl(P,\ Card,\ C_t,\ E_t,\ H_t,\ a_t,\ p_t,\ R_t,\ J_t,\ Contract_{R_t,J_t}\bigr)$$

提案结构：

$$\widehat{\Delta C}_{t+1}=\Bigl(\ \{(id_i,\ s_i')\}_{updates},\ \{(type_j,\ content_j,\ s_j,\ core_j,\ cue_j,\ conflict_j,\ polarity_j)\}_{new}\ \Bigr)$$

其中更新组给已有节点目标强度 $s_i'$，新增组为完整新节点定义。$plan_t$ 为反应计划（话语意图，§8.1）。$p_t$ 为 TRIE 提取的语义锚点（0912 第二轮收敛）：Engine 不得重提或替换 $p_t$，所有实质认知更新须与 $p_t$ 或其直接后果相关，无关 B/D/I 保持不变。**Engine 不输出 appraisal / emotion 提案**（0912 收敛）：$A_t$ 由 EUE 的独立调用在 Updater 约束之后、基于 $C_{t+1}$ 与 Updater 审计产出（§7.1），$E_{t+1}$ 完全由程序从 $A_t$、$\Delta C_t$、$Press_t$ 计算（**Engine 不输出 valence/arousal**）。

### 6.3 Deterministic Updater（程序约束应用）

$$C_{t+1}=Apply\bigl(C_t,\ \widehat{\Delta C}_{t+1},\ R_t,\ J_t,\ \mathcal I_t\bigr)$$

规则（全部触发动作写入审计 notes）：

1. **强度范围**：$0\le s\le4$，越界钳制。
2. **更新幅度**：已有节点的 $|\Delta s|\le Limit(R,J,type)$（§6.1 表），超限截断。
3. **Reject 方向**：$J_t=\text{Reject}$ 时，$\mathcal I_t$ 中的 Belief 禁止正向更新。
4. **Peripheral 核心限制**：$R_t=\text{Peripheral}$ 且 $J_t\ne\text{Accept}$ 时核心 Desire 禁止修改。
5. **新增节点强度上限（0912 收敛）**：新增节点一律以本回合 $Limit(R,J,type)$ 为强度上限，`core=false` 不豁免；唯一豁免：$\text{Peripheral}+\text{Accept}$ 下的 cue 信念（$Limit=\infty$，对应 0911 §25 的 trust/authority/social norm 增强）。
6. **冲突衰减（0912 收敛）**：新增 Belief 与其 `conflicts_with` 中的已有 Belief 冲突时，victim 按新节点强度衰减，但 victim 本轮直接更新与冲突衰减的净变化幅度不得超过 belief 限幅：

$$|already_t-\text{decay}_t|\le Limit(R,J,\text{belief}),\qquad \text{decay}_t\le Limit+already_t$$

其中 $already_t$ 为当轮已发生的直接更新量（可为负），$\text{decay}_t$ 向负方向扣减；超限部分暂缓，矛盾在多轮内渐进消解。新信念过弱退役（inactive）时不产生衰减压力。
7. **Intention 支持（0912 收敛）**：若 $|\Delta I|>\varepsilon=0.5$，须有当轮同方向 B/D 更新（$|\Delta|\ge0.2$）或现存强度 $\ge2.0$ 的 Belief/Desire 支撑，否则截断至 $\varepsilon$。
8. **数量与退役**：$|B|\le4,|D|\le3,|I|\le3$；超限淘汰优先级 退役节点 > 非核心弱节点；非核心强度 $<0.5$ 退役，回升 $\ge0.7$ 重新激活。

## 7. Emotion Update Engine（EUE，收敛自 0911 §32–§34）

> **理论根基：Appraisal Theory + Dimensional Emotion Theory**。Appraisal Theory（认知评价理论，Lazarus / Smith & Ellsworth）：情绪由对事件的三维认知评价产生——目标一致性（GC）、应对潜力（CP）、未来预期（FE），§7.1–§7.2 为其程序化实现；Dimensional Emotion Theory（维度情绪理论，Russell 环状模型）：情绪在效价-唤醒 $(v,r)$ 二维空间连续取值，$c_t$ 仅为展示类别、不参与动力学，§7.3–§7.5 为其程序化实现。

$$E_{t+1}=\text{EUE}\bigl(C_{t+1},\ \Delta C_t,\ E_t,\ GC_{t-1},\ Press_t,\ q_t\bigr)$$

（$A_t=(GC_t,CP_t,FE_t)$ 为本模块**内部中间变量**（§1：不入长期状态）——只被模块内 valence/arousal/category 计算消费，唯一模块外可见形式是审计日志；不列于模块输出。）

内部步骤（§7.1–§7.5 逐步展开）：

1. **A 提案与 A_t 计算**（§7.1，内部中间变量）：Influence 由 EUE 独立调用（Updater 约束后、以 $C_{t+1}$ 与 Updater 审计为输入）产出；Elicit/Social 由 SRR/ERR 合并调用产出——LLM 提案在模块内部产生，不列于模块级签名；
2. **GC 程序重算**（§7.1 公式）；
3. **Valence**（§7.2 公式，$\hat v$ 由 A 三分量决定）；
4. **Arousal**（§7.3 公式，$\hat r$ 由 $|\Delta C|$、$|\Delta GC|$、$Press$ 决定）；
5. **惯性**（§7.4，$\lambda$ 由 $q_t$ 选择）；
6. **Category 校验**（§7.5，LLM 提案 + $(v,r)$ 程序裁决）；
7. **Robustness**（Validation 1.1）：A 提案解析失败 → $GC=CP=FE=0$、无标注、neutral 提案（§2.1）。

### 7.1 Appraisal：提案来源 + GC 逐 Desire 标注 + 程序公式（0912 收敛）

$A$ 提案来源（0912 收敛）：Influence 由 EUE 的**独立调用**产出——在 Updater 约束之后、以 $C_{t+1}$ 与 Updater 审计（截断/禁止/冲突衰减等实际变化）为输入，CP/FE 不再锚定未生效的认知提案；Elicit/Social 由 SRR/ERR 合并调用产出（§8.2、§8.3）。

LLM 输出逐 active Desire 的语义标注：

$$\{(\text{id}_i,\ rel_i,\ gc_i)\},\qquad rel_i\in[0,1],\ gc_i\in[-1,1]$$

程序按 0911 §32.1 公式重算（权重用 **Updater 约束后** 的 Desire 强度，消除提案被截断时的时点错位）：

$$\boxed{GC_t=\frac{\sum_{i\in ActiveGoals} s_i\cdot rel_i\cdot gc_i}{\sum_{i\in ActiveGoals} s_i\cdot rel_i}},\qquad ActiveGoals_t=TopK(s_i\cdot rel_i),\ K=2$$

标注缺失/无效时退回 LLM 提议的 $GC$ 值。$CP_t,FE_t$ 由 LLM 提议（0911 §32.2、§32.3 语义），程序钳制到 $[-1,1]$。

### 7.2 Valence（0912 收敛：$w_1=w_2=w_3=1/3$）

$$\hat v_{t+1}=\frac{GC_t+CP_t+FE_t}{3},\qquad v_{t+1}=(1-\lambda)v_t+\lambda\hat v_{t+1}$$

### 7.3 Arousal（0912 收敛：0911 §34 公式方案，$\hat r$ 由程序计算）

$$\boxed{\hat r_{t+1}=\gamma_1|\Delta C_t|+\gamma_2|\Delta GC_t|+\gamma_3\cdot Press_t}$$

- $|\Delta C_t|=\sum_i|\Delta s_i|/4$：Updater 约束后 BDI 快照差的归一化幅度（4 为强度满量程；含新增/淘汰节点）；
- $|\Delta GC_t|=|GC_t-GC_{t-1}|$：GC 突变，首轮为 0；
- $Press_t$：§4.1 的交互压力等级映射值（Elicit/Social 由合并生成调用标注）；
- 系数（0911 未给，0912 固定）：$\gamma_1=0.6,\ \gamma_2=0.25,\ \gamma_3=0.5$；结果钳制到 $[0,1]$。

$$r_{t+1}=(1-\lambda)r_t+\lambda\hat r_{t+1}$$

### 7.4 惯性系数

$$\lambda=\begin{cases} 0.4, & q_t\in\{\text{Influence},\text{Elicit}\}\\ 0.25, & q_t=\text{Social} \end{cases}$$

### 7.5 Category：LLM 提案 + (v,r) 程序校验（0912 收敛）

LLM 只提案 category，程序按最终 $(v_{t+1},r_{t+1})$ 校验：负向类别（sadness/anxiety/frustration/anger）要求 $v<-0.05$；正向类别（satisfaction/interest/hope/relief）要求 $v>+0.05$；anger 额外要求 $r\ge0.5$。矛盾时改写为由 $(v,r)$ 推导的类别：

$$c_{t+1}=\begin{cases} \text{neutral}, & |v|<0.2\\ \text{anxiety}, & v<0,\ r\ge0.6\\ \text{frustration}, & v<0,\ 0.3\le r<0.6\\ \text{sadness}, & v<0,\ r<0.3\\ \text{interest}, & v\ge0.2,\ r\ge0.6\\ \text{satisfaction}, & v\ge0.2,\ r<0.6 \end{cases}$$

hope/relief 依赖面向未来/过去的评价内容，仅在 LLM 提案且与数值一致时保留。

**消融结论（0912 第二轮，见 Prompt审计0912 §14）**：方案 B（程序主导 category + LLM 仅出 special_affect）在 support 场景把 anxiety 错误推导为 frustration（r=0.5 未达 anxiety 的 r≥0.6 门槛，但场景语义明显是焦虑），且 token 收益可忽略——维持方案 A：LLM 提案完整 category + 程序 (v,r) 校验。

## 8. 三个生成过程（0911 §35–§38）

### 8.1 Cognitive-Grounded Response（Influence：两步，认知与语言分离）

$$u_{t+1}=\text{CGR}\bigl(P,\ C_{t+1},\ E_{t+1},\ H_t,\ a_t,\ plan_t,\ q_t\bigr)$$

$plan_t$ 由 Engine 在 RJ-CTC 中先行输出（§6.2），NLG 调用基于转移后的状态与反应计划单独生成话语。$q_t$ 显式传入（0912 第二轮收敛，Mode-Conditioned 生成）：Influence 表达更新后的认知-情绪反应，Elicit 仅揭示已有状态，Social 仅情感/社会性回应（最终语言层兜底：不产生当前状态中不存在的新承诺）。

### 8.2 State-Revealing Response（Elicit：合并调用出提案，$C_{t+1}=C_t$）

$$\bigl(\hat A_t,\ \mathcal R_t\bigr)=\text{SRR}\bigl(P,\ C_t,\ E_t,\ H_t,\ a_t,\ q_t\bigr)$$

内部步骤：

1. 合并调用输出 $\hat A_t$、逐 Desire 标注 $\{(id_i,rel_i,gc_i)\}$、$Press_t$、$plan_t$、$\mathcal R_t$（标注/$Press_t$/$plan_t$ 为内部中间变量——前者交 EUE 重算 GC 与 arousal，后者交统一 NLG）；
2. EUE 消费 A 提案与 $Press_t$（§7）；
3. $u_{t+1}$ 由统一 NLG 基于 $(C_{t+1},E_{t+1},a_t,plan_t,q_t,\mathcal R_t)$ 生成——消除合并调用中文本只能看到 $E_t$ 的滞后，并让话语自然揭示 $\mathcal R_t$ 中节点的部分内容。

其中 $\mathcal R_t$ 为 revealed_items：被揭示的已有节点 id 列表，供审计（§2 的 State Revelation ≠ State Change 语义；揭示已有状态**不是**认知变化）。

### 8.3 Emotion-Regulating Response（Social：合并调用出提案，$C_{t+1}=C_t$）

$$\hat A_t=\text{ERR}\bigl(P,\ C_t,\ E_t,\ H_t,\ a_t,\ q_t\bigr)$$

与 SRR 共享合并调用实现与统一 NLG 步骤（无 $\mathcal R_t$），但生成语义不同：保持轻量、不触及实质状态，仅允许低幅度情绪调节（$\lambda=0.25$，§7.4）；$plan_t$ 限定为情感/社会性回应，最终语言层兜底禁止产生当前状态中不存在的新承诺（§2.1、Prompt审计0912 §14.1）。

### 8.4 部分揭示与禁用约束（0911 §38，三过程通用）

$$u_{t+1}\ \text{只表达}\ (C_{t+1},E_{t+1})\ \text{的真子集},\qquad u_{t+1}\cap\mathcal V=\varnothing$$

其中 $\mathcal V=\{belief,\ desire,\ intention,\ appraisal,\ processing\ route,\ acceptance/rejection\ label,\ cognitive\ transition,\ \dots\}$ 为禁用词集；且 $u_{t+1}$ 不因 agent 的任务目标而提升合作度（任务中立，0911 §29 规则 6）。

## 9. Conversation End Detector（user_done，0912 补白）

$$\bigl(user\_done_t,\ reason_t\bigr)=\text{CED}\bigl(H_t,\ u_{t+1}\bigr)$$

每轮对 $u_{t+1}$ 做任务中立的结束分类（farewell/离开/拒绝继续交谈）：置真后 `conversation_ended=True`，驱动方停止追问。$user\_done\ne task\_done$（0911 §42）：任务结果由外部 Task Evaluator 读 $z_t$ 判定，模拟器不输出。内部步骤：LLM 分类（输入仅最近 4 条历史与 $u_{t+1}$；`reason` 为纯审计字段，仅 debug 模式请求）→ LLM 失败时退回关键词规则。
